\### 2. TicketHub — Event Ticketing System Design



TicketHub is a system-design exercise focused on planning an event ticketing platform that must handle both normal traffic and sudden spikes in demand.



The scenario includes 2 million registered users, 50,000 daily visitors, and a popular ticket sale where 200,000 people compete for 20,000 seats within 10 minutes.



The design explores how to plan a system that remains responsive while protecting the accuracy of ticket sales.



\*\*Key areas covered:\*\*

\- Functional and non-functional requirements.

\- Traffic estimation and capacity planning.

\- REST API endpoint design.

\- Relational database modelling and SQL.

\- Database relationships, indexes, and example queries.

\- System architecture and request flows.

\- Caching, queues, load balancing, and read replicas.

\- Transactional seat allocation and prevention of double-booking.

\- Trade-offs involving performance, consistency, availability, and fairness.



\*\*Technologies and concepts explored:\*\* SQL, PostgreSQL-style data modelling, REST APIs, caching, queues, and scalable application architecture.



\*\*What I am practising:\*\* Breaking down a real-world problem, estimating demand, evaluating architectural choices, and designing for data correctness and growth.
