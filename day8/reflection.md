\# Day 8 Reflection



The most difficult concept in this course was understanding how a system can handle many users at the same time without losing data correctness. Concepts such as caching, database transactions, read replicas, and queues initially seemed complicated. I overcame this by breaking problems into smaller steps, calculating traffic estimates, drawing architecture diagrams, and following the journey of a request through the system. The TicketHub example helped me understand why checking seat availability in the interface is not enough. The database must make the final decision to prevent double-booking.



Based on the feedback I receive on my capstone presentation, I would improve the architecture diagram and explain more clearly how the components communicate. I would also improve my traffic estimates and demonstrate how the design handles a sudden increase in users. Testing the application under simulated load would help me identify bottlenecks and validate my assumptions.



Next, I want to learn more about SQL, database transactions, REST API development, and authentication. I also plan to practise using Postman to test APIs and learn how to deploy applications online. After that, I want to study monitoring and load testing so I can measure performance instead of relying only on theoretical estimates. These skills will help me become a better software engineer and build reliable applications that solve real-world problems.
